# オンボーディング設計（mobile-onboarding スキル準拠）

対象：ワークスペース（拡張ページ）の初回表示。版は `1`。完了状態と回答は端末内（chrome.storage.local、無い環境では localStorage）にだけ保存し、外部送信しない。

## コンセプトの読み取り

- コンセプト：Webページを見る人が、その場でページ内の画像を見比べ、必要なものだけを迷わず選んで保存し、結果を確認して終える。
- 解決する困りごと：ページの画像を1枚ずつ右クリック保存する手間と、広告や似た画像の中から探す迷い。
- 最初の小さな成功：開いたページの候補から、最初の1枚を選んで保存できること。
- 4条件：①何のためか＝「ページの画像を選んで一括保存する道具」と一文で言える ②使い方＝開く→選ぶ→保存するの3ステップ ③ワクワク＝大量ページでも続きまで候補が届く期待ページ＋試し操作の成功 ④早く使いたい＝接続ページのボタンが今開いているワークスペース本体（最初の成功の場所）へ直結する。

## 実装上の注記

- 進捗は窓ドット（最大5つ表示、1ページごとに1つ動く、数字表記なし）。読み上げでは章名で現在地を伝える。
- 触覚は Web では navigator.vibrate が相当。端末が対応し設定が有効な場合のみ鳴る。
- 試し操作の画像は合成サンプルで、本物の候補ではない。操作の型（押して選ぶ）を体験する目的であり、選択そのものは本体へ引き継がない。
- 計測は外部送信を行わない方針（プライバシー契約）と衝突するため、解析イベントは送らない。ページ表示の計測は未実装として残す。
- 人間の体験確認（初見の人に通してもらう）は未実施。4条件の判定は動作確認までの範囲。
