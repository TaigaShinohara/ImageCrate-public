# プライバシーとデータ保持

ImageCrateは、利用者が開いたページから画像を選んで端末へ保存する拡張です。アカウント、解析・テレメトリ、アプリ用クラウドサーバー、実行時の外部ライブラリはありません。画像の取得には、その画像の配信元への通信が発生します。ストアに掲載する説明は [プライバシーポリシー](PRIVACY_POLICY.md) です。

連絡先: [deeple+imagecratestaff@inkboxmail.com](mailto:deeple+imagecratestaff@inkboxmail.com)。このアドレスはプロジェクトの窓口として掲載しています。報告にはバージョン、Chrome/OS版、合成データでの再現手順を使ってください。署名付きURL、Cookie、トークン、実際の個人メディアやブラウザプロフィールを添付しないでください。

## 保持する情報

| 情報 | 保存先と保持の目的 | 終了・変更したとき |
| --- | --- | --- |
| 元ページのURL・タイトル、画像URL・埋め込み画像・alt等、選択・表示条件 | Chromeのsession storage。収集、表示、元ページの移動確認、保存と再試行に使用 | 作業タブを閉じると不要な元ページ情報・候補・選択・表示履歴を取り除く |
| 保存jobのURL、要求名、download ID、予算、結果不明・後片付け情報 | session storage。保存結果・所有者を照合し、二重保存や別の保存の取消を防ぐ | 結果や後片付けが確定したら終了。タブを閉じても確定まで残る場合がある |
| 実際に保存されたファイルの名前 | session storage。実結果を表示 | 保存先の絶対パスは保持しない。旧sessionの絶対パスもファイル名へ移行する。ファイル名自体に私的な文字列が含まれる場合はある |
| 次回用の保存方法・フォルダ参照 | 端末内のIndexedDB。次の作業で同じ場所を使う | 「次の作業でもこの保存先を使う」をOFFにして適用すると次回用の記憶を取り除く |
| 現在の作業・再試行用のフォルダ参照 | IndexedDB。再読み込み後も同じ保存先を使い、元batchへ再試行する | 次回用のOFFとは別に保持し、使い終わった参照を整理する。未確定の処理に必要な参照は残る |
| 保存済み画像・未完成ファイル、Chromeのダウンロード履歴・キャッシュ | 選択したフォルダやChrome側の領域 | 拡張のsession後片付けとは別。記憶OFFでこれらやChromeの権限を削除しない |

session情報の寿命はChromeのブラウザsessionに従います。一定時間が経っただけで、結果不明の書き込みや保存受付を「未保存」と決めて消去・再試行することはありません。保存先とChromeの履歴を確認してから次の操作を選んでください。

## 次回用の保存先を引き継ぐ設定

保存設定の「次の作業でもこの保存先を使う」は初期ONで、既存の記憶も引き継ぎます。OFFを適用すると、新しく開いた作業ページはChromeのダウンロード先から始まります。現在の作業ページの保存先や中断分の再試行先は変わりません。同じ作業ページの再読み込みに必要な参照は保持します。

ON/OFFは「設定を適用」で確定し、キャンセル・閉じる・Escapeでは取り消します。別タブの古い設定や保存形式だけの変更で、OFFにした次回用メモを勝手に復元しません。保存設定の反映と次回用記憶の更新は異なる保存領域を使うため、一方だけの失敗は画面で区別します。

## 通信とログイン状態

プレビューは初期状態から自動表示します。既存のChrome配信元許可、または元ページを開いた際の一時アクセスを使い、画面に近い収集済み画像を取得します。作業ページごとの再同意は求めません。埋め込みdata画像も端末内で自動処理します。

拡張アイコンから開くだけではChromeの追加アクセス許可を要求しません。未許可の配信元は一覧上部または画像の表示ボタンから許可できます。そのボタンを押したときだけ、対象の配信元をChromeへ要求します。表示更新・スクロール・作業タブ再読み込みからの自動要求も行いません。選択フォルダへの保存・画像変換で必要な配信元の許可は、保存操作時に要求します。「元の形式＋Chromeのダウンロード先」での保存では追加アクセス許可を要求しません。

一時アクセスを使う場合は、現在の作業ページの所有者、収集済み候補、元ページとの同一origin、元ページが移動・終了していないことを確認します。追加許可が必要な配信元だけ操作ボタンを表示します。Chromeの許可要求は対象画像の具体的なscheme・ホストに対して行い、同じホストの全パス・ポートに及びます。権限を自動で要求・拡張することはありません。取消時は生成済みプレビューと処理中の取得を失効させ、その作業ページで一時アクセスへ勝手に切り替えて再取得しません。

プレビュー・変換・選択フォルダへの取得は、許可した配信元に対してブラウザのログイン状態を使う場合があります。管理されたfetchは`credentials:include`、`referrerPolicy:no-referrer`、`redirect:error`を使用します。Cookieの値を読み出すAPIは使いません。

元形式をChromeのダウンロード先へ保存するときは、元URLをChromeへ渡します。Cookie・Referer・リダイレクト・履歴・キャッシュの扱いはChromeが管理するため、上のfetchと同一の通信保証ではありません。署名付きqueryは取得・照合・再試行に必要なため、運用中のURLから一律に除去しません。生のURLをログ・公開Issue・報告へコピーしないでください。

## 元画像とメタデータ

「元の形式」は元byteを保持します。元画像に撮影者・位置情報・コメント等があれば、それも画像とともに残ります。元URLやページ名から作られる保存名にも、私的な文字列が含まれる場合があります。

JPEG・PNG・WebP変換は画像を端末内で描画し直し、新しい画像を出力します。対象形式・フィールドを限定した合成メタデータ試験を行いますが、全形式・全Chrome版の付属情報除去を保証する機能ではありません。画像の画素に写る顔・文字なども残ります。検証した形式と条件は [QA.md](QA.md) に記録します。

## 共有・公開前の確認

保存済み画像や履歴を整理するときは、利用者が選択した保存先やChromeのダウンロード画面で対象を確認してください。ImageCrateが作成していないファイル、別拡張の保存、他の履歴を自動で消す処理は追加しません。

配布前にはextensionの同梱物、文書、Git履歴・作者情報を別々に点検します。現在の文書から環境依存パスや内部リンクを一般化しても、過去のGit履歴から消えたことにはなりません。ライセンス表記と意図したプロジェクト連絡先は出典・窓口として区別します。
